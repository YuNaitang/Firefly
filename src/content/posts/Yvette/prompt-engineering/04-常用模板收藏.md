## 一、工作效率类

### 1.1 邮件撰写

**场景**：催款、客户跟进、内部沟通

```
背景：[收件人与你的关系 + 当前状态]
目的：[你需要对方做什么/对方需要知道什么]
语气：[正式/亲切/紧急/礼貌但坚定]
长度：[不超过X字]
需要避开：[不写什么]
结尾要求：[明确的下一步行动]
```

**示例**：

```
背景：客户王总是合作3年的老客户，欠款30万，上次沟通是上周微信催了两次没回
目的：让客户在本周五前付款
语气：礼貌但坚定，保持合作关系
长度：不超过150字
需要避开：不用"抱歉打扰"、不用"如方便的话"
结尾：明确给出本周五的付款截止日期和逾期处理方式
```

### 1.2 会议纪要

```
请用标准会议纪要格式整理以下会议记录：

议题：[会议主题]
参会人：[列出]
时间：[会议时间]

输出格式：
| 议题 | 讨论要点 | 结论 | 待办事项 | 负责人 | 截止日期 |
|------|---------|------|---------|-------|---------|

额外要求：
- 识别并标注有分歧的观点
- 对不明确的结论标注"待确认"
```

### 1.3 周报/日报整理

```
根据以下工作记录，帮我整理一份[周报/日报]：

工作内容：[粘贴原始记录]

输出要求：
1. 按项目分类
2. 每项标注：完成状态（已完成/进行中/阻塞）
3. 阻塞项标注原因和需要的支持
4. 突出本周的量化成果
5. 格式用表格，最后加下周计划
```

### 1.4 简历优化

```
我是[X年]经验的[岗位]，想转行做[目标岗位/领域]。

请帮我优化以下工作经历：
[粘贴原始经历]

要求：
1. 用STAR法则改写每条经历
2. 突出[核心技能1]和[核心技能2]
3. 每条控制在2行以内
4. 用数字量化成果
5. 整体不超过1页

目标岗位JD关键词：[粘贴描述]
```

## 二、分析推理类

### 2.1 多角度决策分析

```
请从以下角度分析[决策问题]，每个角度给出证据和结论：

角度1：财务可行性（成本、收益、ROI）
角度2：技术可行性（现有能力、技术债务）
角度3：团队资源（人力、时间、技能匹配）
角度4：市场竞争（竞品状态、差异化空间）
角度5：时间风险（deadlines、依赖项）

输出格式：
| 角度 | 证据 | 结论 | 置信度 |
|------|------|------|--------|

最后给出综合建议和推荐优先级。
```

### 2.2 风险预评估

```
请以下方案进行风险评估，按格式输出：

方案描述：[粘贴方案]

输出：
| 风险项 | 发生概率(高/中/低) | 影响程度(高/中/低) | 应对策略 | 预警信号 |
|--------|-------------------|-------------------|---------|---------|

额外要求：
- 每项风险给出一个可观测的预警信号
- 标注哪些风险可以提前规避，哪些只能缓解
- 最后给出整体风险评估和"是否建议推进"的结论
```

### 2.3 批评者模式

```
请站在反对者的立场，严格审查以下方案：

[粘贴方案]

找出最致命的3个漏洞。每个漏洞请给出：
1. 具体风险描述
2. 发生的可能性（高/中/低）
3. 如果发生，影响有多大
4. 哪些信息可以帮你更准确地评估这个风险

不要留情面，越尖锐越好。你的角色是"魔鬼代言人"。
```

### 2.4 逆向推演

```
假设我们的[项目/计划]在[时间]后彻底失败了。

请从"失败"这个终点往前推演，找出可能的原因链条。

每个节点标注：
- 可能的触发事件
- 连锁反应
- 最终的失败表现

最后提问：现在可以做什么来切断这条失败链中最关键的环节？
```

## 三、代码开发类

### 3.1 函数生成

```
语言：[Python 3.12+ / TypeScript / Go]
功能：[一句话描述]
输入：[类型 + 格式 + 示例]
输出：[类型 + 格式 + 示例]

技术要求：
- 版本：[显式声明]
- 允许的库：[列出]
- 禁止的库：[列出]
- 风格规范：[PEP8 / 项目自定义]

质量要求：
- 完整的类型注解
- 中文docstring
- 错误处理（列出需要捕获的异常类型）
- 边界情况处理
- 不要省略任何import

最后写一个简短的main()或pytest测试。
```

### 3.2 代码审查

```
请审查以下代码，按顺序分析：

1. 先理解代码的意图和逻辑流程
2. 检查输入验证和边界情况
3. 检查错误处理是否完善
4. 检查安全隐患（注入/XSS/权限/敏感信息泄露）
5. 检查性能问题（N+1查询、内存泄漏、不必要的循环）
6. 检查代码规范（命名、注释、清晰度）

最后按严重程度（Critical/Major/Minor）排序给出修复建议。

[代码粘贴在这里]
```

### 3.3 Debug

```
我遇到了以下问题：

代码：[粘贴代码]
预期行为：[描述期望的结果]
实际行为：[描述实际的结果]
错误信息：[粘贴错误信息]
已尝试的方案：[列出你已经尝试过的排查步骤]

请帮我分析可能的原因，按可能性从高到低排序。
每个可能原因给出：验证方法 + 修复方案。
```

### 3.4 技术方案评审

```
角色：你是一位资深架构师

请审查以下技术方案，关注：
1. 架构合理性：选型决策是否有充分理由
2. 可扩展性：方案能否支撑未来2倍/10倍的规模增长
3. 运维复杂度：上线后的运维成本和风险
4. 安全合规：是否有安全隐患或合规风险

技术方案：[粘贴方案]

输出格式：
| 关注维度 | 当前评估 | 建议改进 | 优先级 |
|---------|---------|---------|--------|
```

## 四、研究学习类

### 4.1 概念解释（Feynman教学法）

```
请用Feynman教学法解释[概念]：

要求：
1. 用最简单的语言解释，假设听众是一个完全不懂该领域的聪明高中生
2. 避免使用任何专业术语（如果必须使用，请给出通俗的定义）
3. 用一个日常生活中的类比来帮助理解
4. 解释常见的误解：人们通常在什么地方搞错这个概念
5. 最后给一个可以自己动手的简单练习来检验是否真正理解
```

### 4.2 多角度论点分析

```
关于[争议性问题]，请从以下视角分析各方的核心论点和论据：

利益相关方1：[身份]
利益相关方2：[身份]
利益相关方3：[身份]

输出格式：
| 视角 | 核心论点 | 关键论据 | 合理之处 | 局限之处 |
|------|---------|---------|---------|---------|

最后给出：哪些点是各方可以达成共识的、真正的分歧点在哪里。
```

### 4.3 文献/报告速读

```
请帮我快速理解以下[文献/报告/文章]的核心内容：

[粘贴内容]

请按以下格式输出：
1. 一句话概括（不超过50字）
2. 核心论点（3-5个，每个不超过30字）
3. 关键数据/证据（列出最重要的3个数字或事实）
4. 方法论（作者用了什么方法得出结论）
5. 局限性（该研究的3个明显局限）
6. 与我工作的关联（该内容如何应用到我的场景）
```

## 五、创意写作类

### 5.1 文案生成

```
产品/主题：[描述]
目标受众：[画像：年龄/职业/兴趣/痛点]
核心卖点：[列出3个]
发布平台：[小红书/抖音/公众号/Instagram]
字数：[范围]
风格：[参考风格]
需要避开：[禁忌词/表达方式]

输出：[X]个备选方案，每个包含标题+正文+标签
```

### 5.2 头脑风暴

```
关于[主题]，请从以下角度各想[数量]个创意：

角度1：[维度名称，如：技术路线]
角度2：[维度名称，如：商业模式]
角度3：[维度名称，如：用户体验]
角度4：[维度名称，如：营销策略]

每个创意一句话描述（不超过30字）。
请标注你觉得最有潜力的2个创意并说明理由。
```

### 5.3 创意约束生成

```
为[产品/主题]写[X]条[广告语/标题/Slogan]。

约束条件：
- 每条不超过[X]字
- 每条包含一个[具体数字/动词/情感词]
- 不能使用以下词汇：[禁用词列表]
- [X]条走心路线，[X]条幽默路线，[X]条悬念路线
```
